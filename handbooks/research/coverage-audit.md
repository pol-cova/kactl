# KACTL coverage audit for the Mexico finals handbooks

Audit date: 2026-10-18. Repository: [pol-cova/kactl](https://github.com/pol-cova/kactl), examined commit `7532cfe6c1eda7279d6e182b83d41e47e7760658`. This audit reads headers and chapter imports, rather than treating a file listing as evidence that the file appears in a PDF. Root research evidence: `outputs/research-results.md`, its 116-problem atlas, and the year-specific analyses outside this cloned repository.

## What the corpus suggests

The existing research identifies overlapping families: graph/tree modeling 30, ordered data/ranges/offline work25, exact arithmetic26, DP22, counting20, geometry18, strings9, periodicity9, matching/flow8. These are curated memberships, including provisional analyses; they are not official tags, disjoint counts, difficulty rankings, or forecasts. For this team, arithmetic reductions, sufficient DP states, and reliable BFS implementation precede advanced templates even when advanced families recur.

KACTL is strongest at reusable specialist implementations. It does not replace the missing layer of explanations: how decimal input becomes exact integers, why an appended digit changes a remainder by (10r+d)%m, why a DP state retains enough history, how to derive a flow cut model, or how to prove an approximation meets tolerance. The handbooks must supply this layer around the source.

## Important adaptation findings

These are observed code contracts and limitations, not claims that every item is an upstream bug.

1. **Source prelude required.** Snippets use vi,ll,pii,rep,all,sz from contest/template.cpp. SCC and TwoSat use GNU's `a ?: b` syntax. Source-only compilation with an unrelated prelude or strict non-GNU compiler is not assumed.
2. **SCC ordering is reverse topological.** `comp` IDs run from sinks toward sources; inter-component edges go to smaller IDs. Callback storage is reused. Recursive traversal may need stack accommodations.
3. **Biconnected bridges need collection code.** Bridges are recognized only at the marked branch; the callback reports non-bridge blocks. Distinct edge IDs preserve parallel-edge correctness. Self-loops need separate policy; articulation vertices are not returned.
4. **TwoSat uses bitwise literal negation.** `~x` is the intended negative literal. `!x` collapses to0/1 and silently changes the model. At-most-one does not supply at-least-one.
5. **Dinic is residual and mutable.** `calc` returns additional flow on the current residual graph. `leftOfMinCut` reads the final BFS. `addEdge` reverse indices need adaptation if accepting self-loops; avoid them in the chosen model. Use bounded capacities and total flow to avoid overflow. [Dinic source](https://github.com/pol-cova/kactl/blob/7532cfe6c1eda7279d6e182b83d41e47e7760658/content/graph/Dinic.h).
6. **HLD is not a neutral path container.** Root0, connected tree, additive modifications and max queries; values initially follow LazySegmentTree's -1e9 default. Initialize values before adding. Edge mode excludes the LCA's slot. Replacing max by sum needs coordinated changes, and noncommutative paths need ordering. LazySegmentTree includes BumpAllocator.h, so copying HLD code without dependencies is incomplete.
7. **Geometry construction can lose exactness.** SegmentIntersection explicitly warns that integer points truncate fractional intersections and triple-coordinate intermediates can overflow. Point<ll> does not make all operations safe: unit/rotation involve division/floating values. PointInsideHull and HullDiameter assume nonempty input; PolygonArea uses back(). Boundary policy defaults strict for polygon containment. [SegmentIntersection source](https://github.com/pol-cova/kactl/blob/7532cfe6c1eda7279d6e182b83d41e47e7760658/content/geometry/SegmentIntersection.h).
8. **Hashing retains collision risk.** The main hash uses 2^64−1 arithmetic, a different contract from plain unsigned overflow. KMP/Z give deterministic answers for matching. AhoCorasick defaults uppercase A–Z and accepts no empty patterns.
9. **Source recurrence modulus is a placeholder.** LinearRecurrence.h declares mod=5 on an `exclude-line`. Direct inclusion uses5; typeset extraction can remove that line. Contest use must supply the chosen modulus and safe multiplication. [LinearRecurrence source](https://github.com/pol-cova/kactl/blob/7532cfe6c1eda7279d6e182b83d41e47e7760658/content/numerical/LinearRecurrence.h).
10. **Matrix has no implicit modular arithmetic.** Plain ll entries overflow on large powers. Supply a modular type or adapted multiplication and specify row/column transition convention.
11. **FFT precision and NTT length are conditional.** FFT advertises sufficient rounded-integer bound `(sum a²+sum b²)log2N<9e14`. NTT uses998244353 and normalized inputs; its actual padding picks a power of two strictly above output length, so inspect padded N≤2^23. Both define names that collide if directly combined. [FFT source](https://github.com/pol-cova/kactl/blob/7532cfe6c1eda7279d6e182b83d41e47e7760658/content/numerical/FastFourierTransform.h), [NTT source](https://github.com/pol-cova/kactl/blob/7532cfe6c1eda7279d6e182b83d41e47e7760658/content/numerical/NumberTheoreticTransform.h).
12. **Offline templates need modeling code.** MoQueries has intentional `...` callbacks; not standalone compilable code. FT2 requires registering update locations before init. Fenwick order-statistic search requires monotone prefix sums. Its initial search bit1<<25 limits directly supported size. LineContainer provides maxima over integer lines, not arbitrary DP acceleration.

## Delivered specialist appendix

`handbooks/specialists.md` supplies a 33-row API lookup, modeling examples, conventions, bounds, and pitfalls. It contains15 source expansion directives covering strings, directed constraints, matching/flow, basic tree jumps, geometry, line optimization and matrix powers, with dependencies required by that selected pack. HLD, FFT/NTT, Mo and other long specialists are mapped and explained but are not all printed in full; this keeps the primary lookup usable. Core ranges and basic graph traversals belong to the main implementation handbook, so they need not be duplicated here.

Validation performed by this researcher: direct inspection of listed headers and chapter import statements at the stated commit; source expansion paths checked against files. No claim of new exhaustive tests for every upstream snippet, official acceptance for every modeled problem, or a guarantee of contest problem coverage. Final integration and selected compile/smoke tests belong to the root handbook build.
